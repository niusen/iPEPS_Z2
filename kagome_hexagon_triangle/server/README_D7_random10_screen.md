# D7随机初态初筛：固定9000步，不自动延长

旧随机任务使用1e-7的严格SU代理判据，dt=0.0005每段τ=32就是64000步，
最多16段可达1024000步，加上warm-up每seed最多约108万步。
这适合长期细化，但不适合作为十个随机初态的第一轮图案筛选。

新入口为 `run_D7_random10_screen.py`，sh为 `run_D7_random10_screen.sh`。
所有新随机态严格按下面五段演化，之后只测一次完整观测量：

| dt | 请求τ | 完整步数 | 实际τ |
|---|---:|---:|---:|
| 0.03 | 40 | 1333 | 39.99 |
| 0.01 | 20 | 2000 | 20 |
| 0.003 | 5 | 1667 | 5.001 |
| 0.001 | 2 | 2000 | 2 |
| 0.0005 | 1 | 2000 | 1 |

总计9000步。min_tau=max_tau，阶段不会提前结束，也不会自动追加细化段。
SU代理仍记录True/False；未通过不影响进入最终测量或开始下一个seed。
因此`screened`表示已完成筛选协议，不等于SU严格收敛。
重新提交会跳过已测量的筛选结果，不会因为SU代理未通过而继续加步数。

## 接用已经花掉的计算

默认读取服务器旧的
`results/server_D7_random10_h040_C3/`。旧目录只读，新结果另存。

- 如果某seed保存的SU检查点已有至少9000步，直接读取这个较充分演化的态，
  **不再演化，马上做一次最终测量**。包括因SVD失败而中断、但仍有有效检查点的seed。
- 旧seed的最初随机态按字节复制，并核验旧配置、seed、父态和文件指纹，
  不会把别的随机分支混进来。
- 尚未开始或不足9000步的seed，以相同seed的原始随机态执行新的五段9000步日程。
- 保存`imported_steps`和`screening_added_steps`，不会把33万步的旧态写成9000步。
  两种演化预算的结果可用于找候选，严格能量比较时再统一细化。
- 若不想接用旧任务，把顶部`REUSE_LONG_RUN=''`，并选用新的OUT。

## 上传、停止旧任务、启动

服务器已有之前完整随机任务时，上传这三个文件：

1. 新增 `server/run_D7_random10_screen.py`
2. 新增 `server/run_D7_random10_screen.sh`
3. 更新 `server/workflow_random_seeds.py`

保留旧的 `run_D7_random10.py`、workflow_from_state.py、workflow.py、observables.py、
device_support.py和包根算法；新入口复用它们。旧自适应模式的默认行为不变。
本说明与测试不必上传，没有修改SU或CTMRG算法文件。

**先停止旧的长时间随机任务，再启动新的筛选入口。** 用旧任务启动时打印的PID
执行`kill -TERM PID`；不要删结果目录或锁文件。仅覆盖服务器文件不能改变
已经运行的Python进程所加载的日程。这里没有远程停止任何进程。

进入服务器 `kagome_hexagon_triangle/server`，执行：

```sh
sh run_D7_random10_screen.sh
```

仍自动激活pytorch环境、后台运行，生成`logs/D7_random10_screen_时间戳_PID.log`，
并打印实际Python PID。无需外加`&`。停止方式和原来相同。

D=7、seed7101–7110、h=0.4、χ=40、CPU10线程做SU、cuda:1做测量，
CTMRG最多50轮、阈值1e-6。C3受约束，镜面和磁化不固定。

新结果目录：`results/server_D7_random10_h040_C3_screen9000/`。
汇总CSV格式沿用原任务，并保留各seed态、来源、实际步数和收敛标记。
CTMRG未通过者为`screened_CTM_unconverged`，不会被当成可靠收缩结果。
测量中断后重新提交只重试相同快照的测量；不会再做SU。

本机测试只用D=2和短日程，验证固定步数、接用旧检查点及失败后恢复。
没有在本机启动D7优化。此改动也没有声称修复原来的SVD分解数值问题；
接用最后一个有效检查点可以避开再次演化到那个失败位置。
